# 接真实大模型（步骤 3B）

把 Mock 换成真模型：**只改 `backend/.env`，不用改业务代码**。

---

## 一、操作步骤（照做）

### 1. 准备密钥

任选一种（都走 OpenAI 兼容接口）：

| 提供商 | 去哪拿 Key | `LLM_BASE_URL` 示例 | `LLM_MODEL` 示例 |
|--------|------------|---------------------|------------------|
| OpenAI | platform.openai.com | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | platform.deepseek.com | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 其他国内兼容网关 | 按厂商文档 | `https://xxx/v1`（一般要带 `/v1`） | 按文档填模型名 |

### 2. 编辑配置

在终端执行：

```bash
cd /Users/xmiles/cursorProject/CV_Helper/backend
# 若还没有 .env：
cp -n .env.example .env
```

用编辑器打开 `backend/.env`，改成例如（DeepSeek）：

```env
LLM_PROVIDER=openai
LLM_API_KEY=sk-你的真实密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_TRANSCRIPT_MAX_CHARS=20000
```

或 OpenAI：

```env
LLM_PROVIDER=openai
LLM_API_KEY=sk-你的真实密钥
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

注意：

- `LLM_PROVIDER` 必须写成 `openai`（表示「OpenAI 兼容协议」，不是只能用 OpenAI 家）
- Key **不要**提交到 git（`.env` 已在 `.gitignore`）
- 改完必须**重启** uvicorn

### 3. 重启服务

```bash
cd /Users/xmiles/cursorProject/CV_Helper/backend
source .venv/bin/activate
# 若已在跑：终端里 Ctrl+C 停掉再执行下一行
uvicorn app.main:app --reload --port 8000
```

### 4. 验收

浏览器打开：

1. http://127.0.0.1:8000/api/health  
   应看到 `"llm_effective": "openai"`（若仍是 `"mock"` = Key 没读到或 PROVIDER 没改）
2. http://127.0.0.1:8000/  
   侧边栏应显示 `API · openai`
3. **③ 模拟面试**：开始提问 → 自己答 → 看点评是否更具体  
4. **⑥ 真实面经**：粘贴转写 → 提取 / 分析，看是否不像规则 Mock 那么死板

失败时会静默回退 Mock。请检查：Key 是否有效、Base URL 是否带 `/v1`、模型名、本机网络是否能访问该 API。

## 二、转写文本有没有「读取上限」？

| 环节 | 上限 | 说明 |
|------|------|------|
| 粘贴入库（SQLite） | 基本无硬上限 | 一场面试全文都能存 |
| 真模型「提取问答」 | 默认前 **20000 字** | 配置项 `LLM_TRANSCRIPT_MAX_CHARS`；超出部分本次不送给模型 |
| 提取条数 | 最多约 **12 条** | Prompt 约定，避免一次吐太多 |
| Mock 模式单题 | 问 500 / 答 2000 字截断 | 仅 Mock 规则提取时 |

手机转录一整场通常够用；特别长可先删开场寒暄再贴。

## 三、成本注意

会调模型：`interview` 的 start/answer/next，以及 `debriefs` 的 extract/analyze。  
CRUD、标记、列表不调。分析面经时「分析全部」= 每条问答一次调用，条数多会多花钱。
