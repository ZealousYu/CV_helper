# 竞品对照与融合路线

> 原则：**交互与归档跟自己；解析、评分维度、报告结构跟优秀开源学；语音做「正式演练」，文字追问树做「准备」。**

## 产品分工（已定）

| 模块 | 定位 |
|------|------|
| ① 经历库 / ② 自我介绍 | 素材准备 |
| ③ 文字模拟（追问树） | **准备**：打磨答案、建索引树，不要求像真面 |
| **语音面试** | **正式演练**：听题口述，练临场表达 |
| ④⑤ 笔记本 / 知识 | 归档可复习 |
| ⑥ 真实面经 | 真场面复盘 |
| ⑦ JD | 定向补洞 |

## 融合阶段

### A. 对照（本文）✅
定主线与不做什么。

### B. 低侵入增强 ✅ / 进行中
1. **四维评分**（后端已有）→ 前端展示综合分 + 四维条  
2. 简历解析质量（后续：清洗双栏乱序、教育段过滤）  
3. JD 报告结构（已有 API，可再丰满）

### C. 语音面试 ✅ / 进行中
- **读题 TTS**：默认浏览器；配置 `DOUBAO_TTS_*` 后走火山引擎 V3（`/api/voice/tts`），比浏览器自然  
- **听写 STT**：浏览器 Web Speech（MVP）；interview-guide 用 Qwen ASR + WebSocket 流式（后置）  
- **投递会话**：多经历 + 岗位/JD，`/api/sessions`  
- **不做（短期）**：LiveKit、自建 ASR 服务  

### E. 知识库 RAG（参考 interview-guide，后置）
[interview-guide](https://github.com/Snailclimb/interview-guide) 做法（我们不换 Spring 栈，只学流程）：
1. **上传**：PDF/DOCX/MD → Apache Tika 抽文本  
2. **异步向量化**：Redis Stream 消费 → 分块 → embedding → **pgvector** 存 PostgreSQL  
3. **问答**：问题 embedding → TopK 检索 → 拼 context → LLM 流式回答（SSE）  
4. **语音**：Qwen3 ASR/TTS + WebSocket 句级流式  

**CV_Helper 可渐进融合**（保持 SQLite + 追问树主线）：
| 阶段 | 做什么 | 和现有功能关系 |
|------|--------|----------------|
| E1 | 知识汇总支持 **上传 PDF/MD** 附件，先全文检索（无向量） | 补「外部资料」入口 |
| E2 | 本地 **sqlite-vec** 或 pgvector 分块向量 | 知识随机问 / 面经弱答可 RAG 引用 |
| E3 | 语音面试前按 JD **检索知识库** 再出题 | 与投递会话结合 |

当前 **⑥ 知识汇总** = 手工精选卡片；interview-guide **知识库** = 文档 RAG。两者可并存：RAG 入库 → 用户升格为卡片。
