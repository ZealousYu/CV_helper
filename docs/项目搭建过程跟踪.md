> 用途：记录本项目从 0 到可用产品的关键决策、踩坑与解法，便于日后面试讲述。

## 项目一句话

做一款**围绕简历经历生成结构化追问树、并自动归档成可复习资料**的模拟面试助手；核心不是「能聊天」，而是「练完自动变成带索引的面试笔记本 + 知识汇总」。

## 步骤 0：先做产品和交互 Demo（已完成）

### 做了什么
- 写了产品方案（痛点 → 追问树 → 自动归档）。
- 先画清 5～6 个核心页面，再做成可点击的 `demo/standalone.html`。
- 迭代一版：经历可手填/编辑、笔记本详情、知识汇总、JD 匹配报告。

### 当时的疑惑 / 容易犯的错
1. **疑惑**：要不要直接让 AI 出漂亮前端？  
   **解法**：先做中保真交互，避免「好看但跳转漏了」。面试可讲：先验证信息架构，再投入工程。
2. **疑惑**：树是只读展示还是可点跳转？  
   **解法**：必须可点回节点再分支，否则解决不了「索引困难」。
3. **疑惑**：知识汇总和「待练习」要不要合并？  
   **解法**：分开——待练习是轻标记，知识汇总是正式入库可编辑。

### 面试可说的收获
先用 Demo 把主路径跑通，再写代码，减少返工；产品决策（树可跳转、标签一级固定）会直接影响数据结构设计。

## 步骤 1：开始工程化（已完成）

### 做了什么
- 明确下一阶段目标：**接后端 + 持久化 + 大模型**，而不是先美化 UI。
- 因本机暂无 Node/npm，选型为：**Python FastAPI + SQLite**；前端暂时继续用现有 Demo / 静态页调 API。
- 产出跟踪文档 + MVP API/数据模型说明。

### 疑惑与解法
1. **疑惑**：先优化界面还是先接 AI？  
   **解法**：先接 API 验提问质量——产品核心风险在 AI 是否有用，不在样式。
2. **疑惑**：本机没有 Node 怎么办？  
   **解法**：后端用 Python 先落地；前端不阻塞主链路。面试可讲：按环境约束做务实选型。
3. **容易犯的错**：一上来就接真实大模型密钥、六个板块全做。  
   **解法**：MVP 砍范围；LLM 先抽象成 Provider，默认 Mock，有 Key 再切真实模型。

### 本步产出文件
- `docs/项目搭建过程跟踪.md`（本文）
- `docs/MVP-API与数据模型.md`

## 步骤 2：后端骨架（已完成）

### 做了什么
- 在 `backend/` 落地 FastAPI 应用：经历 CRUD、面试 start/answer/next/marks、知识汇总 CRUD。
- 追问树以 **JSON 挂在经历表**上存 SQLite（MVP 不过早拆节点表）。
- LLM 层：`MockLLM`（默认）+ `OpenAILLM`（配 Key 可切）；失败自动回退 Mock。
- 启动时若库为空，写入 2 条种子经历。
- 本地冒烟：health → 列表 → start → answer → next(深挖出 q1.1) → marks → 加入知识汇总，全部通过。

### 关键目录
```
backend/app/
  main.py           # 入口、CORS、种子数据
  models.py         # Experience / KnowledgeItem
  routers/          # experiences, interview, knowledge
  services/llm.py   # Mock / OpenAI 兼容
  tree_utils.py     # 树的查找/更新/加子节点
```

### 怎么启动（你本机）
```bash
cd CV_Helper/backend
source .venv/bin/activate
uvicorn app.main:app --reload --port 8000
```
- 文档：http://127.0.0.1:8000/docs  
- 健康检查：http://127.0.0.1:8000/api/health  

### 疑惑 / 踩坑 / 解法
1. **疑惑**：追问树要不要一开始就拆成节点表？  
   **解法**：MVP 整树 JSON 存经历行里。读写简单，和 Demo 结构一致；真要复杂查询/权限再拆表。面试可讲：先匹配产品结构，避免过度设计。
2. **疑惑**：没有大模型 Key 怎么开发？  
   **解法**：Provider 抽象 + 默认 Mock，接口契约不变；有 Key 只改 `.env`。体现「依赖倒置 / 可替换实现」。
3. **踩坑**：沙箱/权限环境下绑定 `127.0.0.1:8000` 报 `operation not permitted`。  
   **解法**：在本机终端直接跑 uvicorn（不要受限环境）；这是环境问题不是业务 bug。
4. **容易犯的错**：每个小操作都调 LLM（贵、慢）。  
   **解法**：约定只有 start（空树）、answer、next 三处调模型；CRUD/标记不调。

### 面试可说的收获
把「产品里的状态机」落成 REST：`start → answer → next`，树持久化后刷新页面不丢练习进度；用 Mock 先打通契约，再换真实模型，降低联调风险。

## 步骤 3A：前端联调（已完成）

### 做了什么
- `standalone.html` 改为请求后端：经历 CRUD、面试 start/answer/next/marks、知识汇总读写。
- 启动时 `refreshAll()` 拉经历与知识；侧边栏显示 `API · mock/openai` 或「未连接」。
- 后端挂载 `/ui` 静态页，访问 http://127.0.0.1:8000/ 即可打开 Demo（同域，少踩跨域）。
- CORS 在 `allow_origins=*` 时关闭 credentials，避免 `file://`（Origin: null）被拦。
- 验收：库里 `exp_001` 已有 q1（已答+标记）与子节点 q1.1；知识条目仍在；刷新接口数据不丢。

### 疑惑 / 踩坑 / 解法
1. **疑惑**：双击打开 html 会不会跨域失败？  
   **解法**：优先走同端口 `/ui`；并修 CORS（`*` + 不带 credentials）。面试可讲：联调阶段先消除协议差异带来的噪音。
2. **踩坑**：旧 uvicorn 进程没加载最新 `main.py`，根路径仍 404。  
   **解法**：改完静态挂载后要重启（或 `--reload`）。
3. **本步较顺**：业务接口契约在步骤 2 已定好，前端主要是换数据源。

### 面试可说的收获
把「可点 Demo」接到「可持久化 API」后，产品从演示变成可积累练习记录的工具；同域托管前端降低联调成本。

### 本步产出文件
- `demo/standalone.html`（API 联调）
- `backend/app/main.py`（`/ui` 挂载、CORS）
- `demo/README.md`、`backend/README.md`

## 步骤 3B：接真实大模型（配置与文档已就绪，待填 Key 验收）

### 做了什么
- 写出并细化 `docs/接真实大模型.md`：改 `.env` → 重启 → 看 health 的 `llm_effective`；补充 OpenAI / DeepSeek 示例。
- 说明转写「上限」：入库几乎不限；真模型提取默认前 2 万字（`LLM_TRANSCRIPT_MAX_CHARS`）；最多约 12 条问答。
- 配置改为**固定读 `backend/.env` 绝对路径**，避免从别的目录启动读不到；health 增加 `llm_key_set` / `env_file` 便于排查。
- **排查结论（用户反馈仍显示 mock）**：磁盘上 `.env` 仍为 `LLM_PROVIDER=mock` 且无生效 Key（修改时间未更新），多半未保存或只改了注释行。

### 疑惑 / 踩坑 / 解法
1. **疑惑**：没有 Key 能不能宣称「接上 AI 了」？  
   **解法**：工程上「可切换」已完成；「内容质量」必须用真模型 + 真实内容验收。跟踪里 3B 标成「待填 Key」。
2. **疑惑**：面经转写会不会读不全？  
   **解法**：库里存全文；送给模型时截断是为了控 token。默认 2 万字，可在 `.env` 调大。
3. **容易犯的错**：把 Key 写进仓库；或 `LLM_PROVIDER` 写成厂商名而不是 `openai`。  
   **解法**：只写 `.env`；`openai` 表示「兼容协议」，DeepSeek 等也填 `openai` + 改 BASE_URL。
4. **踩坑**：以为改了 env 仍是 mock。  
   **解法**：确认保存的是 `backend/.env`（不是 `.env.example`）；`LLM_API_KEY=` 必须是**未注释**的生效行；改完重启 uvicorn；看 `/api/health` 的 `llm_effective` 与 `llm_key_set`。

### 面试可说的收获
用配置切换 Provider，而不是写死某一家模型；无 Key 时 Mock 保证联调不停，有 Key 后只改环境变量。对长文本主动设「送给模型的上限」，兼顾成本与可用性。排障时用 health 暴露「读的是哪个 env、Key 有没有」，避免盲猜。

### 本步产出文件
- `docs/接真实大模型.md`
- `backend/.env.example`
- `backend/app/config.py`（绝对路径加载 `.env`）
- `backend/app/main.py`（health 排查字段）
- `demo/standalone.html`（转写长度提示）

### 你需要做的（完成 3B 验收）
1. **保存** `backend/.env`：至少包含未注释的  
   `LLM_PROVIDER=openai`、`LLM_API_KEY=sk-...`、`LLM_BASE_URL=...`、`LLM_MODEL=...`
2. 重启 uvicorn
3. 打开 `/api/health`：`llm_effective` 应为 `openai`，`llm_key_set` 应为 `true`
4. 用模拟面试随便答一句「我不知道」——真模型不应再说「结构清晰」

## 步骤 3C：追问树分支规则修复（已完成）

### 做了什么
- 明确规则：**深挖 / 发散** → 当前节点的**子节点**（q1.1→q1.1.1）；**换角度** → **同级兄弟**（q1.1→q1.2；根上则 q1→q2）。
- 后端 `resolve_insert_parent` 按 action 决定挂载点；补单元测试。
- 前端改为优先用 `activeNodeId` 作为基准节点；按钮文案标明 ↓子节点 / →同级；toast 提示新建的 nodeId。

### 疑惑 / 踩坑 / 解法
1. **疑惑（用户发现）**：换角度为什么也在往下长成 1.1.1？  
   **解法**：早期实现把所有「下一步」都 `add_child` 到当前节点，没区分语义。应按产品含义分支：换角度是「同一层换侧面」，不是「再深挖一层」。
2. **容易犯的错**：前端用过期的 `branchFrom`（可能仍是父节点）当 `from_node_id`。  
   **解法**：以当前高亮的 `activeNodeId` 为准。

### 面试可说的收获
树结构不仅是 UI，更是产品语义；「同级分叉 vs 向下深挖」要在数据层就分开，否则笔记本索引会乱。

### 本步产出文件
- `backend/app/tree_utils.py`（`resolve_insert_parent`）
- `backend/app/routers/interview.py`
- `backend/tests/test_tree_branching.py`
- `demo/standalone.html`

## 步骤 4：真实面经汇总（已完成）

### 做了什么
- 新板块 **⑥ 真实面经**：粘贴录音转写 → 保存档案 →「提取问答」→「AI 分析」弱答标红并给优化答法。
- 后端 `Debrief` + `/api/debriefs`（CRUD / extract / analyze）；Mock LLM 可切真模型。
- 弱答可一键「入库到知识汇总」；岗位定制顺延为⑦。冒烟：示例转写提取 3 条并标红弱答。
- 列表/录入页增加可折叠提示：「面试录音文本如何获取？」引导用手机自带录音机 + 系统转写，不强弹窗。

### 疑惑 / 踩坑 / 解法
1. **疑惑**：真实面经和模拟追问树要不要一张表？  
   **解法**：分开——模拟是练习生成的树，面经是真对话归档，硬揉会乱索引。
2. **疑惑**：转写格式不统一怎么办？  
   **解法**：优先识别「面试官/候选人」；失败则空行切分或占位，避免空列表。
3. **容易犯的错**：P0 就接语音转写 API。  
   **解法**：只收已转好的文本，降低依赖；用轻量说明文案代替自建 ASR。
4. **疑惑**：要不要弹窗教用户怎么拿文本？  
   **解法**：用可折叠 tip，空列表/录入页默认展开，有数据后列表页收起，避免打断。
### 面试可说的收获
补齐第三环：**真场面经复盘**。闭环变成「模拟练 → 知识库 → 真场复盘再入库」。

- `backend/app/models.py`、`routers/debriefs.py`、`services/llm.py`
- `demo/standalone.html`

## 步骤 6：AI 代答 / 复习对比 / JD 匹配接模型 + 等待态（已完成）

### 做了什么
- **AI 代答 / 看框架**：不再用写死的 DAU 模板，改为请求 `/api/interview/{id}/draft`，按当前题目生成。
- **笔记本复习**：点「提交并请 AI 对比」后，对比上次答案，返回「进步」和「还可以更好」；不再点完成就关窗。
- **岗位匹配**：从前端假报告改为 `/api/job/match`，用经历库 + JD 调 LLM（此前一直是 Mock 是因为根本没接接口）。
- **面经提取/分析**：全屏转圈 + 进度条，避免以为没点到。

### 疑惑 / 踩坑 / 解法
1. **疑惑**：人工点评已经像真模型了，代答为什么还是套话？  
   **解法**：点评走 `answer` 接口，代答之前只在前端写死一句话，两套路径。要分别接 LLM。
2. **疑惑**：岗位匹配为什么还是 Mock？  
   **解法**：产品上一直是占位报告，与 LLM 开关无关。这次才补 API。
3. **体验**：分析要等几秒，没有反馈会以为没点上。  
   **解法**：统一 loading 遮罩。

### 面试可说的收获
同一套 LLM 抽象要覆盖「提问 / 点评 / 代答 / 对比 / JD」，漏掉哪条用户就会觉得「没接上」。等待态属于可用性，和模型质量同等重要。

## 步骤 7：简历上传解析导入（已完成）

### 做了什么
- 经历库上传区接真链路：PDF / Word(.docx) / txt，或粘贴文本。
- 后端 `POST /api/experiences/parse`：内存抽字（不落盘）→ LLM 拆成经历预览卡；扫描件抽不到字时给明确提示。
- `POST /api/experiences/import`：用户勾选后批量写入现有经历表，不覆盖已有数据。
- 前端弹窗确认（全选/勾选）再导入；缺量化会带 `missing_hint`。
- Mock 无 Key 时按段落粗切，保证 API 契约可跑通。

### 疑惑 / 踩坑 / 解法
1. **疑惑**：要不要做 OCR？  
   **解法**：MVP 不做。扫描件提示换可选中文字的 PDF 或粘贴文本；和 Boss 一样先保「可编辑确认」。
2. **容易犯的错**：解析完直接写入。  
   **解法**：拆成 parse（预览）+ import（确认），对齐招聘站「填完再改」的习惯。

### 面试可说的收获
简历解析是「抽字 + 结构化」两段式，产品关键是确认导入而不是一次识别率；和面经提取共用同一套 LLM Provider 抽象。

- `backend/app/services/resume_text.py`
- `backend/app/services/llm.py`（`parse_resume_experiences`）
- `backend/app/routers/experiences.py`（`/parse`、`/import`）
- `backend/app/schemas.py`、`config.py`、`requirements.txt`
- `demo/standalone.html`

## 面试叙事模板（可直接用）

> 我做了一个简历模拟面试助手。用户不是想多一个 ChatGPT 窗口，而是面试准备时问答散乱、难索引。我先用可点击原型验证「左对话 + 右追问树 + 自动归档」；再工程化时优先做经历/会话持久化和可切换的 LLM 层，而不是先做视觉。树结构 MVP 用 JSON 挂经历表，避免过早拆表；LLM 用 Provider 抽象，无 Key 时 Mock 也能把 API 契约跑通。前端联调阶段把 Demo 接到同一端口的 API，并验证刷新后追问树不丢。过程中刻意把「待练习标记」和「知识汇总入库」拆开，避免信息架构混乱。
